# Repository development

[Agent entry point](../AGENTS.md). Read only the sections relevant to the task.

Paths in this reference retain their original project/repository context; verify details against
current sources.

- Root `.NET 10` solution: `Tempest.slnx`
  - `MarshalLib`, `MarshalLib.Database`
  - `Tempest.Protocol` — gRPC/protobuf contract, C# generated automatically by `Grpc.Tools`
  - `Tempest.CLI` — console app / launcher backend, references `MarshalLib`, `MarshalLib.Database`,
    `Tempest.Protocol`

## Required tooling

- .NET SDK `10.0.100` (see `global.json`, `rollForward: latestFeature`)
- Zig `0.15.2`
- Rust stable (`Tempest.Scripting` Lua modding DLL, `Tempest.UnrealScript`)
- Node.js `>= 22` with Corepack enabled (for the root JS workspace: the launcher and the Studio)

## .NET commands

```bash
# Build the whole solution
dotnet build Tempest.slnx

# Run the CLI (from repo root)
dotnet run --project Tempest.CLI -- --help

# Run a CLI subcommand
dotnet run --project Tempest.CLI -- server --help

# Publish the CLI (AOT by default on Tempest.CLI.csproj)
dotnet publish -c Release Tempest.CLI
# Output: Tempest.CLI/bin/Release/net10.0/publish/
```

Notes:
- Building `Tempest.CLI` triggers an MSBuild target (`BuildZigInject`) that compiles
  `Tempest.CLI/inject/` with `zig build -Doptimize=ReleaseSmall`. Zig must be on `PATH`.

## Task runner

The root `justfile` wraps every project's commands, grouped `utils` / `scripting` / `dotnet` / `js`
/ `launcher` / `studio`; `just` lists them. `just check` runs all verification that needs no game
(.NET build, scripting tests + clippy, unrealscript tests + clippy, JS type checks + lint). See each
project's guide for the raw commands its recipes run.

## Code generation

Do not hand-edit generated files:

- `Tempest.Launcher/src/lib/paraglide/` — generated by `@inlang/paraglide-js` from `messages/*.json`
  via the Vite plugin. Source language is `en`; supported: `en`, `fr`, `es`, `pl`, `ru`.
- `Tempest.Launcher/src/lib/rpc/` — generated from `Tempest.Protocol/**/*.proto` by `pnpm -C
  Tempest.Launcher proto-generate` (uses `protoc --ts_out` + `@protobuf-ts/plugin`).
- `Tempest.Protocol` C# outputs — generated automatically by `Grpc.Tools` on `dotnet build`.
- `Tempest.CLI/inject/zig-out/bin/inject{32,64}.exe` — generated by the `BuildZigInject` MSBuild
  target.

If you change `.proto` files, rebuild the solution and run `pnpm -C Tempest.Launcher
proto-generate`.

## Style / verification conventions

- Do not add or update translations (`messages/*.json` files for `fr`, `es`, `pl`, `ru`) unless
  explicitly told to. English source strings are fine to touch.
- The root `.editorconfig`: tabs for most files, spaces for `.rs`.
- Lint and format are repo-wide in *config*, per package in *execution*: the root `.oxlintrc.json`
  and `.oxfmtrc.json` are found by walking up from each app, and the tools are `"catalog:"` dev
  dependencies of those apps. Per-project differences are oxlint `overrides` (the Studio imports the
  typed IPC contract with relative paths; `*.svelte` and route files relax a few rules). Ignored
  everywhere: generated `src/lib/rpc/**` and paraglide output, `vendor/**` (patched Ruffle),
  `build/`, `dist/`, `.svelte-kit/` and `electron/resources/binaries/`.
- Launcher is an SPA: `+layout.ts` disables SSR/prerender and enables CSR. Static adapter with
  `fallback: "index.html"`.
- TypeScript is strict; `tsconfig.json` extends `.svelte-kit/tsconfig.json`.
- Use each project's existing builds, type checks, lint and tests as listed in its guide.
